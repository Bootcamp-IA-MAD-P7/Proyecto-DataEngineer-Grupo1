## Objective

Expose the three existing process-local ingestion metrics through a
Prometheus-compatible HTTP endpoint without changing their names, types, units,
timing boundaries, labels, or ingestion behavior.

## Context and architecture decision

The repository currently uses dependency-free process-local metric objects and has
no Prometheus client or registry. The smallest compatible design is the official
`prometheus-client` library with a dedicated `CollectorRegistry` and one adapter
collector that reads the existing metric objects. This avoids duplicate metric
definitions and uses the library's supported exposition serialization.

The ingestion entry point starts one metrics server before its retry loop and shuts
it down in `finally`. Binding failure propagates before ingestion starts; shutdown
is orderly after the consumer exits or exhausts retries. The FastAPI query API is
not modified.

## Exposition contract

- **Endpoint:** `GET /metrics`
- **Bind host:** `INGESTION_METRICS_HOST`, default `0.0.0.0`
- **Port:** `INGESTION_METRICS_PORT`, default `9464`
- **Configuration:** these optional environment variables only; the selected port
  is validated by the client/server binding operation.
- **Registry:** dedicated process-local `CollectorRegistry` containing one collector
  backed by the existing HRP-77/78/79 metric objects.
- **Format/content type:** Prometheus text exposition generated by
  `prometheus_client.start_http_server` and `generate_latest`-compatible registry
  behavior; the library supplies the response content type.
- **Process behavior:** values are process-local and reset on restart. Standard
  runtime metrics are not required; HRP-80 guarantees the three HRP metric families.

The logical metric families are:

- `hr_pro_platform_ingestion_messages_consumed_total` — counter.
- `hr_pro_platform_ingestion_processing_duration_seconds` — histogram/timer-style
  duration, serialized with standard histogram count/sum samples.
- `hr_pro_platform_ingestion_persistence_duration_seconds` — histogram/timer-style
  duration, serialized with standard histogram count/sum samples.

HRP-77 remains a monotonic consumed-message counter; no rate is calculated.
HRP-78's processing boundary is unchanged. HRP-79 remains measured around MongoDB
`_persist`, including failed attempts and excluding Kafka commit.

## Scope and exclusions

- **In scope:** official client dependency, registry adapter, ingestion lifecycle
  server, optional host/port configuration, exposition tests, and this spec.
- **Out of scope:** Prometheus deployment, `prometheus.yml`, scrape jobs/intervals,
  targets, alert rules, Grafana, dashboards, API changes, and unrelated Docker
  changes.
- **HRP-81:** Prometheus configuration and deployment are explicitly deferred.
- **HRP-82:** dashboards and visualization are explicitly deferred.
- No metric labels are added; payloads, IDs, correlation keys, exception strings,
  secrets, and raw records are never exposed.

## Accessibility and sustainability applicability

- Accessibility: not applicable — no user-facing interface or visual flow is added.
- Sustainability: applicable in a limited operational sense — one bounded listener
  exposes existing in-memory values without polling or duplicate processing. No
  energy, carbon, or deployment claim is made.
